# DJ PULSE — Electronic Music Intelligence

Telegram Mini App для анализа электронной музыки: тренды жанров, рейтинги диджеев (Global / Rising / Russia),
треки, музыка по странам, алгоритмические выводы и дайджест в чат.
**Бесплатно и без своего сервера:** данные собирает GitHub Actions, приложение живёт на GitHub Pages,
бот работает на бесплатном Cloudflare Worker.

> **Важно прочитать.** Я проверил код автоматическими тестами и открыл собранное приложение в браузере, но в моей
> среде нет доступа к Last.fm, Deezer, MusicBrainz, Wikipedia и Telegram. Поэтому **живой прогон по реальным API
> произойдёт только при вашем первом запуске «Update data»**. Если какой-то источник ответит иначе, чем ожидалось,
> приложение не сломается, а покажет его статус «ошибка» на экране «Обзор → статус обновления» и в логе Actions.
> Подробности — в разделе «Что проверено и что нет».

---

## 1. Как это устроено

```
GitHub Actions (по расписанию)           GitHub Pages                 Telegram
  Python-сборщик ─► data/public/*.json ─► приложение (React) ◄────── кнопка «ОТКРЫТЬ DJ PULSE»
  (Wikipedia, Last.fm, Deezer,            читает JSON из ./data/          ▲
   MusicBrainz, YouTube, RSS)                                             │
                                                                 Cloudflare Worker (бот)
                                                                 /start, /subscribe, дайджест по cron,
                                                                 проверка подписи initData
```

* История копится в `data/history/history.json` (коммитится в репозиторий) — графики и рост считаются по ней.
* Если источник недоступен, остаются прежние данные, а у источника показывается **дата последнего успеха**.
  Один упавший источник не блокирует остальные. Старые данные не выдаются за новые (через 48 ч приложение пишет «Данные устарели»).

## 2. Запуск пошагово (≈ 40 минут, ничего не нужно устанавливать, кроме git)

### Шаг 1. Репозиторий на GitHub
1. Зарегистрируйтесь на github.com → **New repository** → имя `dj-pulse`, **Public** (бесплатный GitHub Pages требует публичный репозиторий), без README.
2. Загрузите проект. В терминале в папке проекта:
   ```bash
   git init -b main
   git add .
   git commit -m "DJ PULSE"
   git remote add origin https://github.com/ВАШ_ЛОГИН/dj-pulse.git
   git push -u origin main
   ```
   (Если терминал не по душе — установите «GitHub Desktop», добавьте папку и нажмите Publish. Не загружайте через веб-форму: она теряет скрытую папку `.github`.)

### Шаг 2. Включить публикацию
**Settings → Pages → Build and deployment → Source: GitHub Actions.**

### Шаг 3. Ключи API (бесплатно)
| Ключ | Нужен? | Где взять |
|---|---|---|
| `LASTFM_API_KEY` | **Рекомендуется.** Без него нет жанровых чартов Last.fm, слушателей артистов и географии слушателей | last.fm/api/account/create → «Create API account» (некоммерческое использование) |
| `YOUTUBE_API_KEY` | Необязательно (подписчики каналов) | console.cloud.google.com → создать проект → «YouTube Data API v3» → Credentials → API key. Квота 10 000 единиц в сутки; используются только дешёвые запросы `channels.list` |

Добавить: **Settings → Secrets and variables → Actions → New repository secret** (имя точно как в таблице).
Без ключей приложение работает на Wikipedia + Deezer + MusicBrainz, а отключённые источники честно помечены «отключён».

### Шаг 4. Первый сбор данных
**Actions → Update data → Run workflow.** Через 5–15 минут появятся данные и приложение опубликуется.
Адрес: `https://ВАШ_ЛОГИН.github.io/dj-pulse/` — откройте его в браузере, чтобы убедиться, что всё работает.
Если запуск красный — откройте лог шага «Collect data»: там написано, какой источник ответил ошибкой.

### Шаг 5. Telegram-бот
1. В Telegram откройте **@BotFather** → `/newbot` → имя (например, `DJ PULSE`) → username (должен заканчиваться на `bot`). Сохраните **токен**.
2. Придумайте **секретное слово** для вебхука (случайная строка из букв и цифр, например `x7Kq29mPz`).

### Шаг 6. Cloudflare (бесплатный аккаунт, карта не нужна)
1. Зарегистрируйтесь на cloudflare.com.
2. **Storage & Databases → KV → Create** → имя `dj-pulse-subs` → скопируйте **ID** и вставьте в файл `bot/worker/wrangler.toml` вместо `PASTE_KV_NAMESPACE_ID_HERE` (можно прямо на GitHub: открыть файл → карандаш → Commit).
3. **My Profile → API Tokens → Create Token → шаблон «Edit Cloudflare Workers»** → скопируйте токен.
4. **Account ID** виден на главной странице Workers & Pages (правая колонка).

### Шаг 7. Секреты бота и публикация
В GitHub добавьте ещё четыре секрета (Settings → Secrets → Actions): `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `BOT_TOKEN` (из BotFather), `WEBHOOK_SECRET` (ваше секретное слово).
Затем **Actions → Deploy bot → Run workflow**. В логе будет адрес вида `https://dj-pulse-bot.ИМЯ.workers.dev`.

### Шаг 8. Подключить бота и Mini App
1. Откройте в браузере `https://dj-pulse-bot.ИМЯ.workers.dev/setup/ВАШ_СЕКРЕТ` — должно ответить `{"webhook":true,"menu":true,"commands":true}`.
   Это включает вебхук, **кнопку меню Mini App** и команды бота.
2. Откройте **Settings → Secrets and variables → Actions → Variables → New variable**: имя `VITE_API_URL`, значение — адрес воркера (без `/` на конце).
3. **Actions → Deploy app → Run workflow** (чтобы приложение узнало адрес воркера).
4. В Telegram напишите боту `/start` → кнопка **«ОТКРЫТЬ DJ PULSE»** откроет приложение внутри Telegram.

Готово. Данные обновляются сами каждый день (07:30 МСК), новости и релизы — каждые 6 часов, дайджест уходит подписчикам в 09:00 МСК.

## 3. Источники данных

| Источник | Что берём | Ключ | Статус в проекте |
|---|---|---|---|
| **Wikipedia Pageviews** (Wikimedia API) | Просмотры статей о жанрах и артистах за год (история сразу) | нет | Подключён. Основа Trend Score |
| **Last.fm API** | Охват тега-жанра, топ артистов и треков по тегу, слушатели артиста, топ артистов страны | да | Подключён (если задан ключ) |
| **Deezer API** (публичная часть) | Электронный чарт с позициями, обложки, 30-сек. превью, фанаты артиста | нет | Подключён |
| **MusicBrainz** | Страна происхождения артиста, теги, ссылки, новые релизы | нет | Подключён (1 запрос/сек; кэшируется) |
| **Wikidata** | Связь артист → статья Википедии | нет | Подключён |
| **YouTube Data API v3** | Подписчики каналов артистов (только `channels.list`) | да | Подключён (если задан ключ), необязательный |
| **RSS**: Mixmag, DJ Mag, Resident Advisor, Attack | Заголовок, ссылка, дата | нет | Подключены; **адреса лент я не смог проверить** — если лента недоступна, она получит статус «ошибка»; адреса меняются в `data/custom_feeds.json` |
| Beatport, SoundCloud | — | — | **Не подключены:** по моей проверке нет бесплатного открытого API для новых приложений. Ограничения не обходим |
| Google Trends | — | — | **Не подключён:** нет официального бесплатного API; неофициальный сбор нарушает условия |

Требование Last.fm выполнено: в разделе «Аналитика → Источники» стоит подпись *Powered by AudioScrobbler*.

## 4. Как считаются показатели (коротко; полностью — в приложении: Аналитика → Источники)

* **Trend Score** — доля 7-дневного среднего просмотров статьи Wikipedia о жанре от лидера среди отслеживаемых жанров. Это **косвенный** показатель интереса, а не число прослушиваний.
* **Изменение 7/30/90 дн.** — сравнение с таким же средним N дней назад. Нет базы — показывается «—», а не 0%.
* **Статусы**: Rising (+10% за 30 дн. и растёт неделя), Declining (−10%), Emerging (малый Score, но +25%), Stable. До 35 дней истории — «Мало данных».
* **Популярность артиста** — средняя позиция среди отслеживаемых артистов по доступным источникам (число источников показывается). Подписчики разных площадок **не складываются** и не выдаются за универсальную меру.
* **Рост артиста** — медиана изменений за 30 дней по источникам; **Rising** — от +15% хотя бы по одному. Популярность и скорость роста разделены.
* **Страна артиста** (MusicBrainz) и **география слушателей** (Last.fm) показаны отдельно и не смешиваются.

## 5. Что проверено и что нет

**Проверено автоматически (48 тестов, все проходят):**
* backend — 25 тестов: расчёт трендов и статусов, нехватка истории → `None`, рост по снимкам, сбой одного источника не блокирует другие, сохранение даты последнего успеха, неполные даты релизов отбрасываются, объединение дублей артистов, режим «только новости»;
* bot — 17 тестов: проверка подписи `initData` (валидная / поддельная / подмена данных / просрочка), отсев недопустимых настроек, расписание daily/weekly, обрезка длинного сообщения, вебхук, подписка и отписка, рассылка по cron с очисткой заблокировавших бота;
* frontend — 6 тестов форматирования + типизация TypeScript (`tsc`) + production-сборка.

**Проверено в браузере** (мобильный размер 390×844, Chromium): все экраны открываются без ошибок; сквозной прогон «настоящий сборщик → JSON → боевая сборка» отрисовывает приложение без плашки DEMO.

**НЕ проверено (нужен ваш первый запуск):**
* ответы настоящих Last.fm / Deezer / MusicBrainz / Wikipedia / YouTube / RSS — тесты используют подставные ответы по документации API;
* работа внутри настоящего Telegram на Android, iOS и Desktop (код использует официальный SDK, `BackButton`, `MainButton`, безопасные зоны и тему Telegram, но на устройствах я не запускал);
* публикация на GitHub Pages и Cloudflare (workflow-файлы синтаксически проверены, но не исполнялись);
* ограничения бесплатных тарифов Cloudflare и квот API — проверьте актуальные условия на сайтах сервисов.

## 6. Известные ограничения

* Рост подписчиков / слушателей / фанатов появляется примерно через месяц после запуска — история для этих показателей копится с первого дня. Рост по Wikipedia доступен сразу.
* Deezer-чарт — вся электроника целиком без деления на поджанры; **чартов по странам в бесплатных источниках нет** (фильтр «Страна» на экране «Треки» отключён и подписан).
* Страна есть не у всех артистов (зависит от MusicBrainz). Теги MusicBrainz пользовательские — выборка релизов по жанру неполная.
* Фото артистов берутся только из публичного API Deezer; если нет — показываются инициалы.
* Тексты алгоритмических выводов и дайджеста пока только на русском (интерфейс — русский/английский).
* Приложение тёмное всегда (по дизайн-заданию), поэтому светлая тема Telegram не применяется.
* Поиск российских артистов использует теги MusicBrainz; часть сцены может не попасть в реестр. Реестр ограничен ~220 артистами; кэш MusicBrainz наполняется по 60 артистов за запуск, поэтому первые дни реестр неполный.
* Вебхук и API настроек бота работают на Cloudflare Worker; без него Mini App полностью работает, но подписку на дайджест сохранить нельзя.
* Подписка на дайджест не хранит ничего, кроме id чата и выбранных разделов.

## 7. Частые действия

* **Добавить жанр:** создайте файл `data/custom_genres.json`:
  ```json
  [{"id": "psytrance", "name": "Psytrance", "wiki": ["Psychedelic trance"], "lastfm_tag": "psytrance", "mb_tag": "psytrance"}]
  ```
  При ближайшем обновлении жанр появится с историей за год.
* **Сменить время обновления:** `cron` в `.github/workflows/update-data.yml` (время в UTC).
* **Поменять RSS-ленты:** `data/custom_feeds.json` — список `{"id": "...", "name": "...", "url": "..."}`.
* **Ручное обновление:** Actions → Update data → Run workflow.

## 8. Структура проекта

```
frontend/           React + TypeScript + Chart.js (Vite)
  src/pages/        Обзор, Жанры, Диджеи, Треки, Аналитика, карточки жанра и артиста
  src/charts/       линейный (период, сравнение, %), столбчатый, круговой, спарклайн
  src/services/     данные, Telegram SDK, настройки, i18n (RU/EN)
backend/            Python-сборщик
  djpulse/collectors/   Wikipedia, Last.fm, Deezer, MusicBrainz, YouTube, RSS
  djpulse/analytics/    Trend Score, статусы, выводы
  tests/
bot/worker/         Cloudflare Worker: вебхук, проверка initData, рассылка
data/               public/ (JSON для приложения), history/, cache/
scripts/make_demo_data.py   DEMO-набор только для разработки интерфейса (вымышленные данные)
.github/workflows/  update-data, update-news, deploy, deploy-bot, ci
```

Локальная проверка интерфейса на демо-данных: `python scripts/make_demo_data.py && cd frontend && npm i && npm run dev:demo`
(в интерфейсе будет заметная плашка **DEMO**; в боевую сборку демо-данные попасть не могут — это проверяется в сборке и в CI).
